Candidate-pool provenance audit
Audited 2026-11-15/16 using local files only.

Conclusion

The best-per-document selection saw every candidate row in the three pinned
published QA datasets. The entire chain also matches the original generation
CSVs/SQLite outcome rows available in the sibling clir-dataset-creation project.
No is_best filter, candidate-rank filter, or question-text deduplication removed
candidates before this experiment's selection. Chemistry's smaller pool already
exists in its generation outputs; three candidates was a maximum, not a fixed
quota. There are TEN question-generator IDs in every corpus, distinct from the
EIGHT embedding models used in the retrieval experiment.

It is inaccurate to describe this experiment as choosing from 30 questions for
every document.

explains 197 rather than 200 winners. EUR-Lex/UN input source-language unit
counts equal their canonical winner counts (194/247).

2. Benchmark code does not apply an upstream winner filter.

src/clir_benchmark/adapters.py:22, DatasetReader.read, streams every matching
Parquet row. src/clir_benchmark/pipeline.py:145, prepare_relevance, reads all qas
rows at line 157 and calls select_candidates at line 170. The best-per-document
branch in adapters.py:338 immediately dispatches to _select_per_document at
line 231, grouping by canonical document and selecting maximum score. The
is_best/rank handling at lines 354-376 belongs to the separate legacy best mode.
Evidence overlays preserve list membership; the experiment config has no overlay.

Current adapters.py and pipeline.py are byte-identical to their archived copies
in artifacts/fir-20261109-all-questions/selected-document-20261110/project/.
Thus this conclusion is supported by the saved execution code, not just a later
implementation. The accompanying JSON records SHA-256 hashes.

All chemistry input is_best fields are null. All EUR-Lex/UN input is_best fields
are false. Selection retained all of them as candidates regardless. Selected
rank-2/rank-3 questions also occur: chemistry 3/0, EUR-Lex 48/8, UN 44/11.
Missing-score candidates remain in the audit but cannot win; none won. Exact
question strings repeated within a source remain separate candidate records
(excess duplicate rows: chemistry 3, EUR-Lex 20, UN 13).

Publication wording and remaining limits

Suggested factual wording: "We selected one maximum-scoring question per
canonical source document from all candidates in fixed published QA snapshots,
covering ten question generators. Candidate-pool sizes vary: median 10 (range
4-20) for chemistry, 22 (8-30) for EUR-Lex and 20 (1-30) for UN. All 638 selected
questions were retained for document-level evaluation."

The audit verifies completeness relative to pinned published datasets and their
identified supplied generation outputs. It does not establish completeness over
all historical/raw API responses, parser rejects, unpublished runs, other files
or later revisions. It does not prove that every historical chemistry task used
a byte-identical saved completion prompt. Candidate counts and upstream failure
or abstention rates differ by corpus/model, so this is not a balanced 30-way
selection design. The generator grader scores are accepted as upstream labels;
their calibration across languages, personas and generators was not validated
here. These are publication limitations, not reasons to alter saved cohorts.

No selection, experiment configuration, benchmark result, source file or model
was changed. No network, paid API, generation or cluster execution occurred.
The companion candidate_pool_provenance.json contains full counts, source paths,
hashes, equality checks and explicitly separated unknowns.
